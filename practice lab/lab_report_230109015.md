### 2.5 Analysis

- **Stride sweep:** Time falls from 424 ms to 388 ms as stride grows, with the knee at 64 B. The effect is mild because each loop iteration costs roughly 150 ns of Python interpreter work, which hides most of the coherence traffic. In C the gap would be several times larger.
- **e(p), stride 1 vs 16 (p = 2 to 8):** Stride 1 has the higher serial-fraction estimate (0.159 vs 0.083 at p = 8). This is the false-sharing signature: contention on the shared cache line shows up as extra apparent serial work.
- **e(p), p = 16 and 20:** The two curves converge near 0.10 to 0.13. Beyond the physical cores, SMT siblings and E-cores dominate, so the cache-line effect is no longer the main limit.
- **Residual overhead at stride 16:** e(p) still rises with p, so non-cache effects remain: process start and join cost, turbo clocks dropping under load, and the hybrid core mix.
- **Noise floor:** The p = 1 runs differ by about 6.4% (2539.5 vs 2701.8 ms) even though there is no contention, so smaller differences should not be over-read.
